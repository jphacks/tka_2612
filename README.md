「今夜は、何を飲む？」に答える、カクテル選びのアシスタント。
味の好みでも、「雨上がりに合う一杯」のような気分でも、思いついた言葉を入れるだけで合うカクテルが見つかります。
バーのメニューを撮れば、**そのお店で頼めるお酒の中から**おすすめを選び、メニューのどこに載っているかまで示します。

## 製品概要

### 背景（製品開発のきっかけ、課題等）

バーや飲み屋のメニューには、カタカナのカクテル名がずらりと並んでいます。
お酒に詳しくない人には、名前を見ても味が想像できず、結局いつもと同じものを頼むか、店員さんに聞きにくくて適当に選ぶことになりがちです。

一方でお店の側も、お客さんが「本当はどんな味を求めていたのか」を知る手段がありません。
注文の記録には、選ばれたお酒は残っても、選ばれなかった理由や求められていた味は残らないからです。

### 製品説明（具体的な製品の説明）

スマホのブラウザで使う Web アプリです。

1. ホームで、飲みたい味や気分を入力する（空欄でもよい）。入力欄の下の候補を押して選ぶこともできる
2. メニューの写真を撮る（または選ぶ）と、写真からお酒の名前を読み取り、データベースのお酒と照合する
3. メニューのお酒の中から、入力に合うものを相性の高い順に5杯おすすめする。おすすめを開くと、メニューの写真上でその名前が書かれた位置に印が付く
4. 写真がなくても、全522件のカクテルを並べた「カクテルの地図」で、入力に近いカクテルを探せる
5. 気に入ったお酒はお気に入りに登録できる。お店はトレンドレポートで、お客さんに求められている味やお気に入りの多いお酒を見られる

### 特長

#### 1. 味でも気分でも、言葉で探せる

「甘くて飲みやすい」のような味の希望も、「失恋した帰り道に」「スパイ映画の主人公気分」のような気分やシーンも、同じ入力欄で受け付けます。
入力文と、お酒ごとに用意した説明文（味・香り・度数の目安・合う場面）を Gemini の埋め込みモデルでベクトルにし、コサイン類似度で近いお酒を探します。
キーワードの一致ではなく意味の近さで探すので、カクテルの名前や用語を知らなくても使えます。

#### 2. メニューを撮るだけで、そのお店で頼める一杯がわかる

メニューの写真を Gemini で読み取り、載っているお酒の名前をデータベースと照合します。
おすすめはメニューに載っているお酒からだけ選ぶので、「おすすめされたのにお店にない」ということが起きません。
おすすめを開くと、メニューの写真上でそのお酒の名前が書かれた位置に印が付くので、そのまま注文できます。
データベースにないお酒は、読み取れたが未登録のお酒として分けて表示します。

#### 3. カクテルの地図で、似たお酒の広がりが見える

全522件のカクテルのベクトルを UMAP で2次元に落とし、味や雰囲気の近いお酒が近くに集まる地図として表示します。
点の色はベースのお酒（ジン・ラムなど）を表します。
検索すると、入力に近いカクテルだけを集めて地図を描き直し、いちばん近いお酒に寄って詳しい情報を表示します。
「おすすめの1杯」だけでなく、その周りにある似たお酒も一緒に眺められます。

#### 4. お店向けのトレンドレポート

お店の人向けに、お客さんの好みを集計したページ（`/store`）を用意しました。利用者向けの画面からはリンクしていません。
- **よく使われる言葉**：入力された文を形態素解析で単語に分けて数え、ランキングとワードクラウドで表示する
- **よく入力された文**：おすすめで入力された文を多い順に表示する
- **お気に入りランキング**：お気に入りの多いお酒を表示する

集計する期間も選べます。

### 解決出来ること

- **お客さん**：カクテルの名前を知らなくても、自分の言葉で好みを伝えるだけで、目の前のメニューから合う一杯を選べる
- **お店**：お客さんがどんな味や気分を求めているかがわかり、仕入れやメニュー作り、おすすめの出し方に生かせる

### 今後の展望

- 英語に対応し、海外のバーや、日本のバーに来た海外のお客さんにも使えるようにする
- お店ごとにレポートを分け、自分のお店のお客さんの傾向だけを見られるようにする
- おすすめへの評価（👍/👎）を集め、以降のおすすめに反映する
- コーヒーや日本酒など、名前から味が想像しにくい他のジャンルにも広げる

### 注力したこと（こだわり等）

- **待ち時間を短くする**：写真を選んだ時点で読み取りと照合を始め、メニュー上の位置はおすすめに決まった5杯の分だけあとから求める。読み取りに使うモデルも、速さを優先して `gemini-3.5-flash-lite`（思考は minimal）にした
- **読み取り中も待たせない**：読み取っている間は、カクテルの地図を眺めながら待てる。終わったらそこからおすすめへ進める
- **お酒のデータを自分たちで作った**：Wikipedia の「カクテルの一覧」に載っている498件に、日本のバー・居酒屋の定番（レモンサワー、カシスウーロンなど）24件を加えた522件。説明文（味・香り・度数の目安・合う場面）は独自に書き、ベースのお酒も13種類に分類した
- **メニューの表記ゆれに強い照合**：中黒・長音・全角半角・大文字小文字・価格・括弧の補足をそろえて照合し、それでも見つからなければあいまい一致で探す
- **スマホで使いやすく**：片手で撮れるよう画面下にシャッターを置き、夜のバーで見やすい暗い配色にした

## 開発技術

### 活用した技術

#### API・データ

- Gemini API
  - `gemini-embedding-2`：入力文とお酒の説明文のベクトル化（768次元）
  - `gemini-3.5-flash-lite`：メニューの写真からお酒の名前と位置を読み取る
- Wikipedia「[カクテルの一覧](https://ja.wikipedia.org/wiki/カクテルの一覧)」：収録するカクテルと材料の参考（説明文は独自に作成し、Wikipedia の文章は使っていない）

#### フレームワーク・ライブラリ・モジュール

- フロントエンド：TypeScript、React 19、React Router（SSR）、Vite、Tailwind CSS
  - umap-js：カクテルの地図の2次元配置（Web Worker で計算）
  - orval：バックエンドの OpenAPI から API クライアントを自動生成
- バックエンド：Python、FastAPI、Pydantic
  - Janome：検索文の形態素解析（トレンドレポートの言葉の集計）
  - SQLite：お気に入りと検索履歴の保存
- 開発環境：Dev Container、uv、ruff・ty（Python のリント・型）、Biome（TypeScript のリント・フォーマット）、GitHub Actions

#### デバイス

- スマートフォン・PC の Web ブラウザ

## 動かし方

Dev Container で開くと、Python（uv）と Node.js の環境と依存ライブラリがそろいます。

1. [Google AI Studio](https://aistudio.google.com/apikey) で Gemini の API キーを発行し、`backend/.env` に書く

   ```sh
   cp backend/.env.example backend/.env   # GEMINI_API_KEY を書く
   ```

2. バックエンドとフロントエンドを、別々のターミナルで起動する

   ```sh
   cd backend && make dev    # http://localhost:8000
   cd frontend && make dev   # http://localhost:5173
   ```

3. http://localhost:5173 を開く。トレンドレポートは http://localhost:5173/store

API の一覧やデータの詳細は [backend/README.md](backend/README.md) を参照してください。
